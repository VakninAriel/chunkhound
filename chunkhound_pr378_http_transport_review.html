PR Overview

Adds a Streamable HTTP transport alongside the existing stdio transport, built on the official MCP SDK's StreamableHTTPSessionManager. Shared tool-dispatch logic is hoisted from stdio.py into MCPServerBase so both transports stay in sync.

Key design decisions are sound:

  • Raw ASGI middleware for bearer auth — avoids BaseHTTPMiddleware buffering SSE
  • CORS middleware ordered before auth middleware so preflight OPTIONS is not 401'd
  • await server.serve() not server.run() — avoids nested event loop
  • Non-loopback host or --cors without --auth-token refused at startup
  • Comprehensive smoke tests: handshake, auth, CORS preflight, session teardown, rejection

The code is well-documented with inline rationale for all non-obvious constraints.

🟡 Medium Findings

🟡 Medium HttpMcpClient always parses SSE — breaks if server returns plain JSON
tests/utils/http_mcp_client.py · _parse_sse_data / send_request

send_request unconditionally calls _parse_sse_data(response.text), which scans for a data: line and raises SubprocessJsonRpcError if not found. The MCP Streamable HTTP spec allows servers to respond with either application/json or text/event-stream. If the SDK ever returns plain JSON for a non-streaming request (e.g. on an SDK upgrade or in stateless mode), all tests fail with a confusing "No SSE data line found" error.

Suggested Fix

content_type = response.headers.get("content-type", "")
if "text/event-stream" in content_type:
    body = _parse_sse_data(response.text)
else:
    body = response.json()
return unwrap_result(body, method)
🟡 Medium TOCTOU port race in _get_free_port() can cause flaky tests
tests/test_smoke.py · _get_free_port

_get_free_port() binds an ephemeral port, records it, then releases the socket — all before the spawned server binds it. Under pytest -n auto (parallel workers), a sibling worker or background OS process can grab that port before the server starts, causing random test timeouts with no clear error message.

Suggested Fix

def _get_free_port() -> int:
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as sock:
        sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        sock.bind(("127.0.0.1", 0))
        return sock.getsockname()[1]

SO_REUSEADDR substantially narrows the race window so the server can re-bind immediately after the helper socket closes.

🟢 Minor Findings

🟢 Minor Default port 5173 collides with Vite's dev server
chunkhound/core/config/mcp_config.py · MCPConfig.port

Port 5173 is Vite's well-known default. Developers running ChunkHound alongside a Vite frontend will get a confusing "Address already in use" error. Consider a less collision-prone default (e.g. 3333 or 8765), or note the conflict in the docs/CLI help.

🟢 Minor MCPConfig.__repr__ not updated for new HTTP fields
chunkhound/core/config/mcp_config.py · __repr__

__repr__ was not updated to include host, port, auth_token, and cors. Debug logs and config validation error messages won't show HTTP settings even when they're the root cause.

Suggested Fix

def __repr__(self) -> str:
    parts = [f"transport={self.transport!r}"]
    if self.transport == "http":
        parts += [
            f"host={self.host!r}", f"port={self.port}",
            f"auth_token={'' if self.auth_token else None}",
            f"cors={self.cors}",
        ]
    return f"MCPConfig({', '.join(parts)})"

Mask the token value to prevent leaking it into logs.

🟢 Minor SubprocessJsonRpcError name is misleading in HTTP context
tests/utils/jsonrpc_envelope.py · SubprocessJsonRpcError

SubprocessJsonRpcError is now the base exception for both subprocess and HTTP clients, but the name implies subprocess-only origin. When HttpMcpClient raises it for a 401 or a missing SSE frame, callers reading the traceback have to look past the misleading class name.

Consider renaming to McpClientError in jsonrpc_envelope.py, keeping the old name as an alias in subprocess_jsonrpc.py's __all__ for backwards compatibility.

🟢 Minor test_mcp_http_session_teardown doesn't verify 404 on terminated session
tests/test_smoke.py · test_mcp_http_session_teardown

After terminate_session(), the test asserts pytest.raises(SubprocessJsonRpcError) on the follow-up request — but that's satisfied by any non-200 (401, 500, network error), not specifically a 404 from a terminated session. A 500 regression would pass the test silently.

Suggested Fix

with pytest.raises(SubprocessJsonRpcError) as exc_info:
    await client.send_request("tools/list", timeout=5.0)
assert "404" in str(exc_info.value), (
    f"Expected 404 for terminated session, got: {exc_info.value}"
)

✅ What's Done Well

  • Raw ASGI middleware for bearer auth — avoids BaseHTTPMiddleware body buffering that would break SSE. Well documented.
  • CORS ↔ auth middleware ordering — CORSMiddleware is outermost so OPTIONS preflight isn't 401'd. Rationale documented in docstring and test.
  • Security guards at startup — non-loopback host or --cors without --auth-token is refused in Config.validate_for_command before any socket opens. Error messages are actionable.
  • secrets.compare_digest — timing-safe token comparison throughout.
  • await server.serve() — avoids nested event loop; comment explains why server.run() would fail.
  • Shared base class refactor — tool dispatch in MCPServerBase._register_common_tool_handlers() keeps stdio and HTTP in sync automatically.
  • Comprehensive smoke tests — protocol handshake, session teardown, health endpoint, bearer auth (no token / wrong token / correct token), CORS preflight ordering, and startup rejection are all covered.
  • _terminate uses psutil process tree — correctly handles uv run child/grandchild processes on all platforms.
  • Logging note in module docstring — explicit warning not to silence logging in http_server.py (unlike stdio) captures a non-obvious constraint exactly where a future reader needs it.
