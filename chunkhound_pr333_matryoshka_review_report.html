Adds variable-dimension (Matryoshka) embedding to OpenAI and VoyageAI providers. Users can now request lower-dimension vectors without switching models, reducing storage costs and enabling quality comparisons. The PR also bundles several genuine bug fixes (env bool parsing, force-kill deadline, non-retryable error propagation) and a key refactor: removing the duplicate EmbeddingProvider Protocol from embeddings.py.

Strengths

🧪
Comprehensive test suite. 1,895 lines of new matryoshka tests plus updates to existing test files. Covers init-time validation, runtime discovery, client-side truncation, server-side truncation, custom endpoints, error paths, and dimension mismatches for both providers.
🔴
Non-retryable error propagation. EmbeddingProviderError subclasses are re-raised before the retry loop in both _embed_batch_internal (OpenAI) and _embed_single_batch_locked (VoyageAI). This prevents dimension mismatches and config errors from polluting retry counters and error stats.
🧩
Single source of truth for the Protocol. The duplicate EmbeddingProvider Protocol in embeddings.py is eliminated. All callers now import from interfaces/embedding_provider.py. EmbeddingManager type annotations updated accordingly.
🔧
Genuine bug fixes bundled. Env bool parsing now fails explicitly on garbage values (e.g. "maybe", "2"), the force-kill deadline is separated from the graceful timeout, and VoyageAI's _rerank_via_sdk now guards against a None rerank model that previously caused AttributeError.
🌐
Runtime dimension discovery for custom endpoints. Custom OpenAI-compatible endpoints (Ollama, vLLM, etc.) can reuse known model names without triggering static validation. Dimension is discovered from the first untruncated response, with a documented 1536 pre-discovery fallback.
🏗️
Shared validation utilities. Validation logic extracted into shared_utils.py and reused across OpenAI, VoyageAI, and config layers. No duplication of range/type checks between providers.

Findings

High

HIGH dims property mutates state and logs a warning — side effect in a getter

The dims property in OpenAIEmbeddingProvider logs a logger.warning and flips self._warned_default_dims = True inside a property getter. Properties are expected to be pure reads; callers that access .dims for dimension introspection (e.g. in dimension validation, repr, or health-check) will trigger a spurious log and a state mutation they didn't intend.

chunkhound/providers/embeddings/openai_provider.py ~L650

Suggested fix

Move the warning + flag to _ensure_client or the first embed() call, where "no static metadata and no discovered dims yet" is explicitly an active-use signal — not a read signal.

# In _embed_batch_internal, BEFORE the API call:
if not self._warned_default_dims and not self._uses_static_model_dims():
    self._warned_default_dims = True
    logger.warning(
        f"No static config for model '{self._model}'; using 1536 until "
        "first embed() call discovers the runtime dimension."
    )
# dims property becomes a pure getter:
@property
def dims(self) -> int:
    if self._output_dims is not None:
        return self._output_dims
    if self._uses_static_model_dims():
        return self._model_config[self._model]["dims"]
    if self._discovered_native_dims is not None:
        return self._discovered_native_dims
    return 1536

Medium

MEDIUM Dead code in extract_cli_overrides — embedding_output_dims attr never exists

The CLI argument is registered as --output-dims / --embedding-output-dims. argparse uses the first long option to derive the dest, so the namespace attribute is always args.output_dims. The second block that checks hasattr(args, "embedding_output_dims") can never be True and is dead code.

chunkhound/core/config/embedding_config.py ~L714–723

Affected code 
# Current (has dead block):
if hasattr(args, "output_dims") and args.output_dims is not None:
    overrides["output_dims"] = args.output_dims
if (
    hasattr(args, "embedding_output_dims")       # ← always False
    and args.embedding_output_dims is not None
):
    overrides["output_dims"] = args.embedding_output_dims  # ← dead

# Fix: remove the second block entirely
MEDIUM _bare_provider test helper missing attrs added in this PR

_bare_provider() in provider_test_helpers.py constructs an OpenAIEmbeddingProvider via __new__(), bypassing __init__. This PR adds _qwen_model_config and _qwen_rerank_config inside _configure_qwen_batch_sizes, which is called from __init__. The bare provider is missing these attributes. Any future test that exercises Qwen paths on the bare provider will hit AttributeError.

tests/unit/provider_test_helpers.py ~L47–90

Suggested fix

Add the missing attrs to the bare provider builder:

provider._qwen_model_config = None
provider._qwen_rerank_config = None

Or consider adding a _set_defaults() classmethod to OpenAIEmbeddingProvider that initialises instance attributes without connecting to external services, making __new__()-based helpers unnecessary.

Minor

MINOR Magic number 1536 used as default dims in 3+ places

The pre-discovery fallback dimension 1536 appears inline in dims, native_dims, and model config. Extracting a OPENAI_DEFAULT_DIMS = 1536 constant (alongside OPENAI_DEFAULT_MODEL already in constants.py) would consolidate them and make future model updates easier.

chunkhound/providers/embeddings/openai_provider.py ~L640, ~L690, ~L377

MINOR _trust_runtime_output_dims() name is counter-intuitive

The method returns True for custom (non-official) endpoints to skip static model validation. The name "trust runtime" doesn't communicate that "trust = skip static checks". A clearer name would be _is_custom_openai_endpoint() or _skip_static_model_validation().

chunkhound/providers/embeddings/openai_provider.py ~L547

MINOR FakeEmbeddingProvider.supported_dimensions returns only 2 values when output_dims is set

When output_dims=512 and dims=1536, the fake returns [1536, 512], implying only those two dimensions are valid. A real matryoshka model returns a range. This is fine for the current tests but could cause false-passing tests if future tests check in supported_dimensions for intermediate values.

tests/fixtures/fake_providers.py ~L254

Architecture Notes

What is correct

  • Validation layering — init-time validation (fail fast for known official models) vs. embed-time validation (fail gracefully for unknown/custom models) is the right separation. The _validate_output_dims_config_for pattern shared across __init__ and update_config avoids duplicated rules.
  • Exception hierarchy placement — core/exceptions/embedding.py is the right home; re-exported through interfaces/embedding_provider.py for convenience is clean.
  • VoyageAI supports_reranking() — verified against current main: rerank_model defaults to VOYAGE_DEFAULT_RERANK_MODEL ("rerank-2.5"), not None, so the new logic (return self._rerank_model is not None for official API) is not a behavioral regression.
  • Force-kill deadline fix — _FORCE_KILL_DEADLINE = 2.0 as a module-level constant (not hardcoded at use site) and replacing the real subprocess mock test with an actual SIGTERM-ignoring process is strictly better.

Potential concern: two-phase dimension validation in _embed_single_batch_locked (VoyageAI)

The method validates raw dims before truncation and final dims after. For unknown models where _expected_raw_dims() returns None, the first validation is skipped — correct. The double-validation is a bit verbose but adds defense in depth and is well-commented.

Breaking changes

  • supports_matryoshka() removed from Protocol (replaced by property metadata). If any downstream code called this directly it will break — but a search of the current repo shows no callers.
  • _discovered_dims renamed to _discovered_native_dims — internal only, no external callers.
