🔍 Feature Overview

Git-diff search enables semantic search scoped to changed code in a commit range. Instead of searching the entire indexed codebase, ChunkHound runs git diff, parses the unified diff into chunks, embeds them on-the-fly, and computes cosine similarity against the query — all in memory, with no writes to DuckDB.

📅

Last-N Commits

--last-n 20 expands to HEAD~20..HEAD. Ideal for "what changed recently?" queries without needing to know exact hashes.

🎯

Single Commit

--commit-hash abc1234 expands to abc1234^..abc1234. Pins search to exactly the diff introduced by one commit.

📐

Commit Range

--commit-range v2.0..HEAD uses git's own ref syntax. Full release-window searches, branch comparisons, tag-to-tag diffs.

Ephemeral chunks only. Language.GIT_DIFF chunks are never written to DuckDB. They exist in memory for the duration of a single search call and are discarded afterwards. The indexed database is read-only during diff search — no schema changes required.

vector_source Modes

ModeBehaviorWhen to use
diff Cosine-similarity over in-memory diff chunks only. DB not queried. Focus on what changed in this range.
db Pure passthrough to original SearchService. Diff ignored. Large diffs — skip embedding overhead.
both Run diff + DB concurrently via asyncio.gather; merge results by score desc; dedup on (file_path, start_line). Full-context query: what changed AND what exists.

_resolve_commit_range() — source 
def _resolve_commit_range(
    commit_range: str | None,
    commit_hash: str | None,
    last_n_commits: int | None,
) -> str | None:
    """Resolve mutually-exclusive commit inputs to a single git revision range."""
    if sum(x is not None for x in [commit_range, commit_hash, last_n_commits]) > 1:
        raise ValueError("Provide at most one of: commit_range, commit_hash, last_n_commits.")
    if commit_hash is not None:
        return f"{commit_hash}^..{commit_hash}"    # single commit
    if last_n_commits is not None:
        return f"HEAD~{last_n_commits}..HEAD"    # last-N window
    return commit_range                          # explicit range or None
_inject_diff_service() — source (condensed) 
async def _inject_diff_service(
    services: DatabaseServices,
    effective_commit_range: str,
    vector_source: str,
    embedding_manager: Any,
) -> DatabaseServices:
    raw_diff = await run_git_diff(effective_commit_range, cwd=find_project_root(None))
    diff_chunks = parse_diff_to_chunks(raw_diff, max_chunk_chars=MAX_DIFF_CHUNK_CHARS)
    if len(diff_chunks) > MAX_DIFF_CHUNKS:
        diff_chunks = diff_chunks[:MAX_DIFF_CHUNKS]  # OOM guard
    diff_embeddings = []
    if diff_chunks and embedding_manager is not None:
        emb_result = await asyncio.wait_for(
            embedding_manager.embed_texts([c.code for c in diff_chunks]),
            timeout=_EMBED_TIMEOUT_SECONDS,  # 120s
        )
        diff_embeddings = emb_result.embeddings
    vs = vector_source if vector_source in ("diff", "db", "both") else "both"
    diff_service = DiffAwareSearchService(
        original=services.search_service,
        diff_chunks=diff_chunks,
        diff_embeddings=diff_embeddings,
        vector_source=vs,
        embedding_manager=embedding_manager,
    )
    return services._replace(search_service=diff_service)

💻 CLI Quick-Start

Mode 1 — Last-N Commits

# Find authentication changes in the last 20 commits
chunkhound search "authentication middleware" --last-n 20

# Internally resolves to: git diff HEAD~20..HEAD
# Default --vector-source diff  (diff-only, fastest)

Mode 2 — Single Commit

# Inspect what changed in one specific commit
chunkhound search "database migration schema" --commit-hash d9aef3fd

# Expands to: git diff d9aef3fd^..d9aef3fd

Mode 3 — Commit Range with Both Sources

# Full release-range query — merge diff and indexed DB results
chunkhound search "API breaking changes" \
    --commit-range v2.0..HEAD \
    --vector-source both

# Also works with deep research:
chunkhound research "what changed in the auth module?" --last-n 50
Large ranges: embedding 500 diff chunks can take up to 120s. For very large ranges (e.g. HEAD~500..HEAD), use --vector-source db to skip diff embedding entirely and search the full indexed database instead.

⚖️ Design Decisions

①
Decorator pattern over inheritance DiffAwareSearchService wraps any duck-typed SearchService rather than subclassing. All non-semantic methods (search_regex, get_chunk_context, get_file_chunks) delegate transparently via self._original. Callers receive a DatabaseServices namedtuple with search_service replaced via ._replace() — zero changes in any call site. chunkhound/services/diff_aware_search_service.py · SearchServiceProtocol (@runtime_checkable)
②
In-memory only — never persisted Language.GIT_DIFF is an in-memory-only chunk type. Diff chunks are never written to DuckDB. This avoids polluting the persistent index with transient search data, keeps the DB schema unchanged, and allows concurrent normal indexing to proceed without conflict. chunkhound/core/types/common.py · Language.GIT_DIFF (ephemeral, not indexed)
③
10,000 character chunk boundary JSON/HTML diffs are approximately 1:1 chars-to-tokens. With a 16,384-token embedding model limit, 10k chars is a safe upper bound. The parser handles single overlong lines (minified SVG, minified JS) by splitting at char boundaries within the line itself, so a 25k-char single line becomes 2–3 addressable chunks rather than being silently truncated. chunkhound/core/git_diff/parser.py · MAX_DIFF_CHUNK_CHARS = 10_000
④
Allowlist regex for ref validation All commit refs are validated against _SAFE_REF = re.compile(r'^[a-zA-Z0-9_.^~/:@{}\-]+$') before any subprocess call. Any arg starting with -- is also rejected. Defense-in-depth: git itself validates refs, but the regex blocks shell injection via crafted argument values (e.g. --output=/tmp/x) before they reach the subprocess boundary. chunkhound/core/git_diff/runner.py · _SAFE_REF regex · test_unsafe_ref_rejected
⑤
asyncio.gather for "both" mode — zero latency penalty Diff search is pure in-memory NumPy (no I/O). It returns in microseconds. Running it concurrently with the DB query via asyncio.gather(diff_search, db_search) means the merged mode costs exactly as much as the DB query alone. Dedup after merge on (file_path, start_line) ensures no result is double-counted when the same hunk exists in both the diff and the DB index. chunkhound/services/diff_aware_search_service.py · search_semantic() · "both" branch
