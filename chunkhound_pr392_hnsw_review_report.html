What this PR does

The old SQL mixed provider/model/path/threshold filters into the same query as the HNSW ANN scan, so DuckDB's query planner couldn't use the HNSW index with those filters present. This PR restructures the HNSW query path to do ANN candidate retrieval as a clean single-table scan using array_cosine_distance(), applying filters afterward. It adds a duckdb_hnsw_enabled toggle (enabled by default) to disable HNSW entirely, changes the semantic result window cap to 1,000 rows when HNSW is active and unlimited when it's disabled, changes pagination so pagination["total"] now returns None (callers should rely on has_more/next_offset), and redefines threshold as an inclusive cosine-similarity floor (1 - distance) rather than a distance ceiling — a breaking change documented with a migration guide in CHANGELOG.md. Includes 15 new/modified test files.

Findings

Undocumented new failure mode in multi-hop pagination Medium
chunkhound/services/search/multi_hop_strategy.py:122
Multi-hop search now raises ValueError when offset + page_size exceeds min(semantic_result_window_cap, effective_result_limit) (default 500). The CHANGELOG documents the DuckDB-provider-level [0, 1000) cap but not this multi-hop-specific 500-row limit, so callers can hit a surprising unhandled error.
Suggested fix Document the 500-row multi-hop pagination ceiling in CHANGELOG.md's migration guide, and/or catch it in the MCP/CLI layer to return a clear "reduce offset or page_size" error instead of a raw ValueError bubbling up.
Unbounded O(N) pagination cost when HNSW is disabled Medium
chunkhound/providers/database/duckdb_provider.py:1660
With duckdb_hnsw_enabled=false, pagination is exact and uncapped but uses a plain ORDER BY ... LIMIT ? OFFSET ? with no supporting index — each page costs O(N) over the matching set. Deep pagination on large, HNSW-disabled repos degrades linearly with no ceiling, unlike the HNSW path which is capped at 1000 rows.
Suggested fix Either document this as an accepted trade-off of disabling HNSW (operators opting out of ANN accept O(N) exact scans), or apply the same 1000-row window cap to the exact-mode path for consistency.
Budget-exhausted error path has no test coverage Minor · test-coverage
chunkhound/providers/database/duckdb_provider.py:1920
The RuntimeError path in _require_complete_vector_limit (budget exhausted with zero results) is never exercised by any test in the new suite. A regression here — e.g. silently returning [] instead of raising — would go undetected.
Suggested fix Add a unit test that forces the budget-exhausted zero-results branch and asserts RuntimeError is raised.
New CI lane runs unconditionally and gates pages-artifact Minor
.github/workflows/ci.yml:9
The new hnsw-contract-tests lane (including a slow 10k-row recall test) runs unconditionally on every push/PR with no path filtering, adding CI cost for unrelated changes, and it gates the pages-artifact job.
Suggested fix Add a paths filter (e.g. chunkhound/providers/database/**, tests/**duckdb**) so the lane only runs when relevant code changes, or decouple it from gating pages-artifact.

What checked out fine

  • SQL injection safety: parameterization is consistent throughout the rewritten query builders — table names are built from internal integer dimensions, never raw user input.
  • Breaking change is properly documented: the threshold semantics change (distance ceiling → inclusive similarity floor, 1 - distance) is a real breaking change but is explicitly covered in CHANGELOG.md's Breaking Changes / Migration Guide sections, and it fixes a pre-existing inconsistency with the LanceDB provider, which already used similarity-floor semantics.
  • Pagination/overfetch logic is sound: overfetch/candidate-widening logic, pagination look-ahead, and hybrid-window-cap propagation (semantic_window.py, hybrid_utils.py) were traced end-to-end with no off-by-one or double-counting bugs found.
  • Unusually strong test coverage: real (non-mocked) DuckDB providers, HNSW-vs-brute-force recall assertions, EXPLAIN-plan assertions proving HNSW vs sequential-scan usage, and a dedicated CI lane (CHUNKHOUND_REQUIRE_HNSW=1) that fails closed if VSS/HNSW isn't actually available.
