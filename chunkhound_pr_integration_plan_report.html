import math

def l2_normalize(vector: list[float]) -> list[float]:
    norm = math.sqrt(sum(x * x for x in vector))
    if norm == 0.0:
        return vector
    return [x / norm for x in vector]

def apply_client_side_truncation(
    embeddings: list[list[float]], output_dims: int
) -> list[list[float]]:
    """Truncate to output_dims and L2-normalize (required for cosine similarity)."""
    return [l2_normalize(v[:output_dims]) for v in embeddings]

PR #339 Database Compaction — HNSW Fragmentation Recovery

Removes manual checkpoint tracking (which defeats DuckDB's direct-write WAL optimization) and replaces it with: (1) mandatory batch compaction boundaries post-chunking and post-embedding, and (2) probabilistic auto-compaction after write operations. Uses a three-phase atomic swap to safely rebuild the database file.

Key insight: Manual CHECKPOINT calls every 100 ops prevent DuckDB from using its fast-path WAL optimization. PR #339 removes this entirely, replacing it with infrequent, stateless, atomic compaction.

Three-Phase Atomic Swap

  1. Checkpoint + Backup: Flush WAL to disk, create a copy of the live DB as .compaction_backup
  2. Copy + Rebuild: Build a new canonical DB file containing only ChunkHound tables (drops unknowns)
  3. Atomic Swap: Replace live file with compacted version; restore backup if interrupted (crash safety)

3 Implement three-phase atomic compaction
def compact_database(self) -> int:
    """Atomic three-phase rebuild: checkpoint → copy canonical tables → swap."""
    # Phase 1
    self._executor_checkpoint()
    backup_path = self._executor_backup_database()
    try:
        # Phase 2
        new_db_path = self._executor_rebuild_canonical_database()
        # Phase 3
        self._executor_atomic_swap(new_db_path, backup_path)
        self._executor_rebuild_indexes()
    except Exception:
        # Restore backup on any failure
        if backup_path.exists():
            backup_path.replace(self._db_path)
        raise
    finally:
        backup_path.unlink(missing_ok=True)
    return os.path.getsize(self.db_path)
4 Implement fragmentation measurement

Use three data points to estimate fragmentation ratio:

  • PRAGMA database_size — allocated file blocks
  • pragma_storage_info — block-level allocation metadata
  • os.path.getsize() — physical file size

Health thresholds: < 1.5 = healthy, > 3.0 = fragmented, > 5.0 = critical
